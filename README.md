# Детектор нарушений прохода через турникет (СКУД)

Программа смотрит видео с камеры у турникета и сверяет число зелёных сигналов индикатора с числом людей, прошедших через проём. Нарушения прохода она отмечает в журнале, а решение по каждой тревоге принимает оператор.

| Файл | Назначение |
|---|---|
| `turnstile_detector.py` | детектор по видео (v4), логика правил, запуск |
| `multicam.py` | все камеры в одной программе: общая пачка для нейросети, мозаика, общий журнал |
| `autosetup.py` | авторазметка проёмов: индикаторы, линии, турникет или ворота |
| `tracker.py` | лёгкий трекер людей для режима многих камер |
| `hud.py` | всё, что на экране: баннер тревоги, мозаика, русские подписи |
| `skud_check.py` | сверка с журналом СКУД: красный пропуск, лимит сопровождения, повторный проход |
| `cam.example.json` | пример конфига камеры (обычный проём и грузовые ворота) |
| `skud.example.csv`, `points.example.json` | пример выгрузки СКУД и соответствия точек |
| `start.bat`, `start.command` | запуск двойным кликом (Windows / Mac) |
| `tests/` | 43 автотеста: сценарии логики, авторазметка, трекер, экран, сверка СКУД, сквозной прогон |

## Какое правило чем ловится

| Нарушение (правила объекта) | Тревога | Источник |
|---|---|---|
| Проход вдвоём по одному прикладыванию | `NO_GREEN`, `ZONE`, `WIDE` | видео |
| Проход без пропуска | `NO_GREEN` | видео |
| Передача пропуска | `HANDOVER` (руки через турникет), `PASSBACK` (повторный вход без выхода) | видео + СКУД |
| Сопровождение по красному пропуску | `RED_ESCORT` | СКУД |
| Больше 3 сопровождаемых (белый, жёлтый, синий) | `LIMIT` | видео (приблизительно) + СКУД (точно) |
| Перелаз через тумбу | `CLIMB` | видео (нужно разметить тумбы) |
| Пролаз под триподом | `NO_GREEN` (треки сшиваются через линию) | видео |
| Проход в запрещённую сторону | `REVERSE` (если `one_way: true`) | видео |

## Что изменилось по сравнению с v3

1. **Потеря трека на линии больше не прячет нарушение.** Раньше проход не засчитывался, если нейросеть теряла человека у турникета или трекер менял ему id. Так бывает при пролазе под триподом, когда кто-то загораживает человека, и в плотной очереди. Теперь потерянный трек с одной стороны и новый с другой «сшиваются» в один проход: параметры `relink_sec` и `relink_dist`.
2. **Тревоги не глушат друг друга.** В v3 у всех тревог проёма была общая пауза 4 с. Если за кем-то без пропуска сразу проходил второй человек, тревога записывалась одна, а `ZONE` гасила следующий за ней `NO_GREEN`. Теперь тревоги о проходах (`NO_GREEN`, `WIDE`, `CLIMB`, `REVERSE`) пишутся для каждого человека. Пауза `cooldown` осталась только у тревог-состояний (`ZONE`, `HANDOVER`, `LIMIT`), причём у каждого типа своя. Записи одного события объединены столбцом «инцидент», так что оператор разбирает инцидент целиком.
3. **Блик не даёт разрешения.** Зелёный засчитывается, только если горит `green_frames` кадров подряд (по умолчанию 2). Повторно сигнал засчитывается только после того, как индикатор погас.
4. **Перелаз через тумбу (`CLIMB`).** В `--setup` можно разметить отрезки тумб и ограждений (поле `barriers`). Если человек пересёк такой отрезок, а не проём, это перелаз.
5. **Сверка с журналом СКУД (`skud_check.py`).** Цвет пропуска на видео не определить, а в журнале СКУД он есть. Поэтому правила про красный пропуск и про лимит сопровождения проверяются там точно. Ещё к каждой тревоге детектора подставляются номер и цвет ближайшего по времени пропуска.
6. **Быстрая обработка записей.** Для видеофайла параметр `process_fps` (например, 10) задаёт, сколько кадров в секунду анализировать. Нейросеть запускается не на каждом кадре, поэтому запись 25 кадров/с анализируется примерно в 2,5 раза быстрее.
7. **Память больше не растёт.** В v3 словарь учтённых проходов только пополнялся и при работе сутками рос без ограничения. Теперь старые записи удаляются.
8. В конце работы выводится сводка по типам тревог.

## Запуск одним кликом (все камеры)

- **Windows:** дважды кликните `start.bat`.
- **Mac:** дважды кликните `start.command`. Если Mac не даёт его открыть, один раз нажмите правой кнопкой → «Открыть».

При первом запуске скрипт сам ставит библиотеки в папку `.venv` (5–10 минут, нужен интернет), нейросеть скачивается автоматически. Дальше по шагам:

1. **Ссылки.** Все камеры перечисляются в `links.txt`, по строке на камеру: `CAM-01 https://.../index.m3u8`. Если файла нет, программа создаст образец и откроет его в Блокноте. Для одной камеры можно просто вставить ссылку в окно. Ссылки из «Аргуса» живут около суток, поэтому каждый день обновляется только этот файл.
2. **Разметка новых камер — автоматически.** Программа 3 минуты смотрит все новые камеры одновременно и сама находит индикаторы, проёмы и их тип: маленький (турникет, трипод) или большой (грузовые ворота). Затем по каждой камере показывает картинку с разметкой: Enter — принять, `m` — разметить вручную кликами, `s` — пропустить. Картинки сохраняются в `cameras/<камера>_auto.jpg`.
3. **Работа.** Открывается окно с мозаикой всех камер (20 камер — сетка 5×4). Камера с тревогой загорается красной рамкой, сверху появляется баннер «НАРУШЕНИЕ CAM-04 проём A…», на Windows звучит сигнал. Клик по камере или цифра 1–9 открывает её крупно, Esc возвращает к мозаике, `f` — во весь экран, `q` — выход. Камера без видео показывает «НЕТ СИГНАЛА».

При первом запуске программа спросит, писать ли подписи на экране по-русски. Потом это меняется в `cameras/params.json`: `"ru_text": true` или `false`. Для одной камеры есть ключ `--ru`. Кириллица рисуется через Pillow; если подходящий шрифт не найден, программа сама вернётся к латинице.

Журналы: `out/<камера>/...` как раньше и общий `out/violations_all.csv` по всем камерам.

### Как работает авторазметка

- **Индикатор** — место, которое почти всё время красное и иногда становится зелёным. Одежда идущих людей тоже бывает красной и зелёной, но в каждой точке недолго, поэтому её программа отсекает. Если за время наблюдения пропуск никто не приложил, берётся устойчиво красное пятно, а проём помечается «проверить».
- **Проём** — по траекториям людей, прошедших у индикатора. Программа берёт главное направление движения и «талию» потока, то есть место, где люди идут теснее всего; линия проёма проводится поперёк потока в этом месте.
- **Маленький или большой.** Ширина проёма сравнивается с шириной человека в том же месте кадра. Если проём шире 2,2 человека, это грузовые ворота. Поэтому одинаково работает для турникетов у камеры и вдали.
- **Ограничения.** Для проёма нужно хотя бы 3 прохода за время наблюдения. Через грузовые ворота ходят 1–2 раза в сутки, поэтому их обычно приходится размечать вручную (`m`) или наблюдать дольше (`--observe 1800`). Тумбы для `CLIMB` авторазметка не ставит, их размечают вручную.

### 20 камер и производительность

Кадры всех камер идут в нейросеть одной пачкой, у каждой камеры свой трекер и своя логика. По умолчанию каждая камера анализируется 8 раз в секунду (`cam_fps`), то есть 20 камер — это 160 кадров/с.

- **На обычном процессоре этого не хватит.** На тестовом 4-ядерном сервере без видеокарты вышло 35 кадров/с на все камеры, около 1,7 кадра/с на камеру. Этого мало для надёжного счёта проходов.
- **Для 20 камер нужен компьютер с видеокартой NVIDIA.** Программа выберет её сама (`"device": ""`). На видеокарте я не замерял, поэтому скорость нужно проверить на месте.
- **Без видеокарты** уменьшайте `cam_fps` (не ниже 4–5) и `imgsz` (например, 480) или делите камеры на два компьютера (два `links.txt`).

## Запуск из командной строки

```
pip install -r requirements.txt
python turnstile_detector.py --selftest                      # «Логика в порядке.»
python turnstile_detector.py --setup --config cam.json --source "ссылка"
python turnstile_detector.py --calib --config cam.json
python turnstile_detector.py --config cam.json --source "свежая ссылка"
```

Режим многих камер из командной строки:

```
python turnstile_detector.py --auto                 # авторазметка всех камер из links.txt
python turnstile_detector.py --auto --source "ссылка" --camera CAM-07   # одна камера
python turnstile_detector.py --multi                # все размеченные камеры в одном окне
python turnstile_detector.py --multi --ru           # то же с русскими подписями
```

Разметка в `--setup` проходит так же, как раньше: 8 кликов на проём (4 угла зоны, 2 точки линии, 2 угла индикатора). После них программа спросит, сколько тумб разметить. На каждую тумбу нужно 2 клика вдоль её верха или основания. Если ввести 0, `CLIMB` выключен.

Результаты сохраняются в папку `out/<камера>/`: `violations.csv` (теперь со столбцом «инцидент»), `passes.csv` и кадры нарушений.

### Сверка с СКУД

```
python skud_check.py --skud выгрузка.csv --violations out/CAM-01/violations.csv --map points.json
```

Выгрузка — это CSV со столбцами `время; точка; пропуск; цвет; направление`. Если в вашей системе столбцы называются иначе, задайте имена ключами `--col-time`, `--col-card` и т.д. Программа создаёт два файла:

- `skud_report.csv` — нарушения по журналу (`RED_ESCORT`, `LIMIT`, `PASSBACK`);
- `violations_skud.csv` — тревоги детектора с номером и цветом пропуска.

### Тесты

```
pip install -r requirements-dev.txt
python -m pytest -q
```

## Новые параметры (`"params"` в конфиге)

| Параметр | По умолчанию | Что задаёт |
|---|---|---|
| `green_frames` | 2 | сколько кадров подряд должен гореть зелёный |
| `relink_sec` | 1,5 с | сколько ждать потерянного человека на другой стороне линии |
| `relink_dist` | 1,2 | насколько далеко от линии он мог потеряться (в ширинах проёма) |
| `track_forget` | 5 с | через сколько забыть невидимый трек |
| `incident_sec` | 4 с | тревоги ближе этого объединяются в один инцидент |
| `process_fps` | 0 (все кадры) | для видеофайла: сколько кадров/с анализировать |
| `recross_dist` | 1,5 | если человек отошёл от линии дальше (в ширинах проёма), следующий проход считается заново |
| `ru_text` | false | подписи на экране по-русски |
| `cam_fps` | 8 | много камер: сколько кадров/с анализировать с каждой |
| `device` | "" (сама) | `"cpu"` — процессор, `"0"` — первая видеокарта |
| `sound` | true | звук при тревоге (Windows) |

Общие параметры для всех камер задаются в `cameras/params.json`, параметры одной камеры — в `"params"` её файла.

Остальные параметры и их значения по умолчанию те же, что в v3. Если индикатор не распознаётся, уменьшите `sat_min` до 25 или `min_colored` до 2. Если много ложных `ZONE`, увеличьте `zone_sec`. Если сшивание треков даёт ложные проходы в толпе, уменьшите `relink_sec` до 0,8.

## Что по-прежнему остаётся ограничением

- Программа не запускалась на камерах объекта. Проверка была такая: автотесты на синтетических сценариях и тестовое видео с настоящими людьми (вырезаны из фотографий) и настоящей нейросетью yolov8n-pose. На этом видео 20 камер одновременно насчитали все 13 проходов из 13 и ровно одно нарушение («паровозик») на каждой камере, без ложных тревог. Авторазметка нашла оба проёма с ошибкой около 10 пикселей. Реальные камеры сложнее: перспектива, блики, толпа.
- Сшивание треков может ошибиться в плотной встречной толпе: если одного человека потеряли, а с другой стороны в этот момент появился другой.
- Двое, слившиеся в одну рамку, не ловятся, если камера смотрит вдоль их плеч.
- На верхних fisheye-камерах нужно дообучение модели на кадрах объекта.
- Для 20 камер с полной частотой анализа нужна видеокарта (см. выше).
- Ссылка из «Аргуса» живёт около суток. Для постоянной работы нужен доступ к API потоков.
